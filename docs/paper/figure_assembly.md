# Figure assembly

`just paper-figures` assembles the multi-panel paper figures from pipeline panels.
It is an opt-in target: it is not part of `just run-all`, `just reproduce` or the results catalog, and it writes nothing under `data/processed/`, so the baseline roster is unaffected.

```bash
direnv exec . just paper-figures-dry   # preview
direnv exec . just paper-figures       # build every figure that has a layout
direnv exec . just test-paper-figures  # test the assembler
```

## What it builds

Each figure is one layout file, `configs/paper_figures/<figure_id>.yaml`.
The output is a standard figure package under `data/paper_figures/figures/<figure_id>/`: `assembled.png`, `assembled.pdf`, `legend.md` and a `summary.json` envelope.
`scripts/validate_figure.sh` checks each package as it is built, with `PROCESSED_DIR=data/paper_figures`.

The assembly computes no value.
Every number in an assembled figure is drawn by a source panel, and the envelope's `panels` list records the source file, clip box and origin of each one.

## Where panels come from

A layout names each panel by a path relative to the checkout.

| Source path | What it is |
| --- | --- |
| `data/processed/...` | An ordinary pipeline output, used as it is and clipped where the layout says. |
| `data/paper_figures/panels/<figure>/...` | A figure renderer run again with `JUMP_FIGURE_NO_CAPTION=1`, so the panel has no caption band. The caption text is still computed and written to that folder's `summary.json`. |
| `data/paper_figures/panels/tables/...` | Tables and one bar chart drawn by `notebooks/paper-figure-tables.py` from analysis outputs. |
| `assets/paper_figures/...` | A versioned input that no rule can regenerate, marked `origin: static` in the layout. |

The panel rules in `rules/paper_figures.smk` take their inputs from the figure rules they repeat and read their outputs off the layouts.
A layout that names a panel no rule writes fails the dry run and `tests/test_paper_figure_layouts.py`.

Analyses declare a summary or a completion marker, not every plot they write.
Where a layout uses such a plot, the figure waits for that analysis's marker, so `just paper-figures` builds the analyses it needs from a checkout that has only the inputs.
The layouts draw on the `all`, `batch_and_source7`, `explore` and `srijit` targets, so expect a full run when none of them has been built.

### Static inputs

These panels are not regenerated by this repository:

- `assets/paper_figures/posted/`: regions of existing paper figures.
  They supply the example micrographs, the mean-versus-median aggregation tables, and the assay-endpoint prediction curves, none of which has a pipeline source.
- `assets/paper_figures/replicate_number/`: the panels of the replicate-number analysis, whose code is not in this repository.

An assembled figure reports its count of static panels as `numbers.static_panels`.

### Panels clipped from captioned figures

The UMAP panels are clipped from the captioned figure PDFs under `data/processed/`, with a clip box that excludes the caption.
They therefore show the embedding of the run they are built from.
UMAP coordinates differ between GPU models, so these panels match the published ones only when the pipeline ran on the reference hardware.

A clipped vector panel still contains the clipped-away content inside the PDF, invisible on the page but found by text extraction.
Flatten an assembled PDF before sending it to a journal.

## Layout files

```yaml
id: figure_paper_example        # equals the file name
title: What the figure shows    # no manuscript figure number
width: 7.2                      # inches; omit to fit the widest row
justify: true                   # spread each row across the width
rows:
- - src: data/processed/some-analysis/plot.pdf
    width: 3.4                  # final width in inches
    clip: [0.0, 0.05, 0.5, 1.0] # page fractions: x0, y0, x1, y1
  - - src: data/paper_figures/panels/tables/a_table.pdf   # a nested list is a vertical stack
      width: 3.4
      title: Shown beside the panel letter
    - src: assets/paper_figures/posted/example.png
      width: 3.4
      origin: static
      letter: false             # continues the panel above; `label: C` pins a letter instead
```

Panel letters are assigned in reading order and drawn on the figure.
They never appear in `legend.md`: the legend keys panels by position ("Top row, left"), because letters change when a figure is rearranged.
Each legend clause gives the panel's source file and the caption its renderer computed.

Widths are set per panel because the renderers use different canvas sizes and type sizes, so one figure-wide scale would give mismatched type.
The assembler refuses a layout with a missing source, a clip or mask box outside the page, a row wider than the figure, or a title wider than its panel.

## Environment

`notebooks/paper-figure-assembly.py` declares its dependencies inline and runs through `uv run --script`.
PyMuPDF is not part of the pinned Pixi environments, so the script imports nothing from `jump_production`, and its tests are skipped by `just test` and run by `just test-paper-figures`.

## Limits

- Renderer titles remain inside some panels, and type sizes are uneven across panels drawn by different renderers.
- Clip boxes were set by eye against the current renderers.
  A renderer change that moves a plot inside its canvas needs the layout's clip box updated; the assembler checks that a box lies inside the page, not that it frames the intended plot.
- Inspect every assembled PNG at full size after changing a layout or a renderer.
